# TG Tunnel Kit — устойчивый SSH-доступ к своему телефону

Комплект для доступа к **вашему собственному** устройству (Termux) с вашего VPS
через постоянный SSH-туннель. Всё инициируете вы, своим ключом, к своему серверу.

```
   ┌─────────────┐        исходящее SSH-соединение        ┌──────────────┐
   │  Телефон    │  ───────────────────────────────────▶ │     VPS      │
   │  Termux     │   autossh -R 2222:localhost:8022       │  sshd        │
   │  sshd :8022 │ ◀───────────────────────────────────   │  порт 2222   │
   └─────────────┘        обратный проброс порта          └──────────────┘
                                                                 │
                                              ssh -p 2222 u0_a123@vps
                                                                 ▼
                                                        вы, с любого места
```

## Порядок (10 минут)

### Шаг 1 — VPS

```bash
# заменить плейсхолдеры на свои: VPS_HOST, TUNNEL_USER, TUNNEL_PORT
sudo bash vps/setup-vps.sh
```

Скрипт: создаёт пользователя-туннель без shell, прописывает `AllowTcpForwarding` и
`GatewayPorts`, открывает порт. Перед запуском откройте файл и проверьте переменные.

### Шаг 2 — телефон

```bash
pkg install git -y       # если ещё нет
# перенести папку device/ на телефон (adb push, scp, Syncthing — как удобно)
bash device/install-termux.sh
```

Скрипт: ставит `openssh autossh termux-services`, генерирует ключ, кладёт `~/.ssh/config`.

### Шаг 3 — обмен ключом

```bash
cat ~/.ssh/id_ed25519.pub
```

Эту строку добавьте на VPS в `/home/<TUNNEL_USER>/.ssh/authorized_keys`
(образец — `vps/authorized_keys.example`).

### Шаг 4 — поднять туннель

```bash
sv-enable autossh
termux-wake-lock
```

### Шаг 5 — проверка

С ноутбука:

```bash
ssh -p 2222 <PHONE_LOGIN>@<VPS_HOST>
```

`PHONE_LOGIN` — результат `whoami` в Termux (вида `u0_a123`, **не** `root`).
Порт телефона в Termux — **8022**, он всегда пробрасывается как внутренний.

## Главное правило

Пароль нигде не используется. Только ключ. `TUNNEL_USER` создаётся с `nologin` и
`restrict,permitlisten` — так туннель даёт доступ ровно к одному порту телефона и
не превращается в дополнительную точку входа на VPS.

## Что читать дальше

- **`docs/01-elements.md`** — разбор каждого элемента по отдельности: зачем он,
  что сломается без него, как убедиться, что работает.
- **`docs/02-alternatives.md`** — чем можно заменить каждый элемент: другой транспорт
  (Tailscale, WireGuard, Cloudflare Tunnel), другой супервизор, другой режим порта.
- **`docs/03-troubleshooting.md`** — «Connection refused», «Permission denied»,
  «туннель отваливается» и т.д.

Область применения: **только ваши собственные устройства**. Туннель к устройству
другого человека без его ведома — это уже неправомерный доступ, и этот комплект
для такого не предназначен.
